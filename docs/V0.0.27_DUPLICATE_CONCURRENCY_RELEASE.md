## Review finding and accepted boundary

`recomputePotentialDuplicateFlags_()` reads the current Transactions extent, calculates every derived flag, and writes the full `Potential_Duplicate_Flag` column. Without serialization, overlapping script executions can finish out of order and allow an older result to overwrite a newer result.

The impact is limited to derived review state. This adapter does not write `Duplicate_Key`, `Is_Duplicate`, transaction facts, or financial summaries. A document lock serializes script executions that cooperate by acquiring the same lock; it does not block human edits in the Google Sheets UI and does not replace Issue #6's broader multi-sheet transaction-atomicity work.

## Implementation

- Acquire `LockService.getDocumentLock()` before reading the Transactions sheet or its last row.
- Wait up to 10 seconds with `tryLock()`.
- If the lock is unavailable, throw an explicit error before any Sheet read or write.
- Hold the lock across formula flush, the single Duplicate_Key read, pure calculation, and the single Potential_Duplicate_Flag write.
- Release every acquired lock in `finally`, including empty-ledger and exception paths.

## Automated verification

`pnpm test` verifies:

- the lock is acquired before the ledger extent is read;
- the lock covers the complete read/write window;
- success releases the lock;
- a timeout performs no Sheet read or write and does not release an unacquired lock;
- a Sheet exception still releases the lock;
- existing exact matching, beyond-row-5,000, 12,000-row batching, trigger filtering, and migration safety remain green.

The Node test validates the locking contract, not real parallel Apps Script scheduling. Development runtime verification remains required after a separately approved push.
