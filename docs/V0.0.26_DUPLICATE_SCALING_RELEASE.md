## Architecture

`calcPotentialDuplicateFlags_()` accepts plain Duplicate_Key values and counts them in one O(n) pass. It returns `Yes` for every occurrence of a repeated nonblank key, `No` for a unique key, and blank for a blank key. Matching is exact and case-insensitive.

`recomputePotentialDuplicateFlags_()` is the Sheet adapter. It flushes pending Duplicate_Key formulas, reads the real Duplicate_Key column extent once, and writes the corresponding Potential_Duplicate_Flag column once. It never writes Duplicate_Key, Is_Duplicate, amounts, dates, categories, ownership, or summary cells.

The adapter runs:

- once after Add Transaction;
- once after Add Shift has posted both Wages and Tips rows;
- after direct edits to fields that feed Duplicate_Key; and
- on demand through **Refresh Duplicate Flags**.

Data Health Check independently derives the expected flags and reports drift without changing cells.

This design follows Google's Apps Script guidance to [perform batch operations](https://developers.google.com/apps-script/guides/support/best-practices) instead of alternating per-cell reads and writes. The bound [`onEdit(e)` simple trigger](https://developers.google.com/apps-script/guides/triggers) may modify its own spreadsheet, and script-initiated `setValues()` calls do not fire it again.

## Formula-to-value transition

The first refresh replaces existing per-row Potential_Duplicate_Flag formulas with derived `Yes`/`No` values. This is intentional. Duplicate_Key formulas remain intact, while direct edits and supported entry tools keep the derived flag values current.

The old formula used a fixed row-5,000 range. Restoring that formula is not an acceptable steady-state rollback because it recreates the defect. Before development deployment, capture the current Potential_Duplicate_Flag formulas as local-only recovery evidence. If live verification fails, restore the v0.0.25 source and that captured development-only column state; do not deploy either version to production.

## Automated verification

`pnpm test` covers:

- case-insensitive exact matching;
- blanks and unique keys;
- both occurrences of a duplicate whose second row lies beyond row 5,000;
- 12,000 rows with one Duplicate_Key read and one Potential_Duplicate_Flag write;
- automatic wiring in Add Transaction and Add Shift;
- direct-edit trigger filtering so unrelated edits do not scan the ledger;
- absence of the old `$5000` formula boundary; and
- unchanged v0.0.24/v0.0.25 maintenance safety tests.
