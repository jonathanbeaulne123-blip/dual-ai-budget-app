## Small coherent preservation plan

1. Restore a source-owned authored planting corridor definition, reproduced from baseline branch plan inputs with the identical authorCurve sampling and every-second-point + last selection. Keep it distinct from SKILL_BRANCHES, which remains actual physical geometry. A baseline JSON snapshot may be used only once exported from the exact baseline and provenance recorded; the early /tmp snapshot lacks sufficient provenance.
2. Generate the original candidate plan using those immutable source corridors and original scenery frames. Preserve the exact random call sequence, occupancy marks, successful-return behavior and stand completion counts. The entire unfiltered output must compare byte-equivalent to baseline, full and lite, before calling preservation complete.
3. Only AFTER generation, deterministically remove plants whose actual visible/collision envelope intersects newly approved landing geometry. Do not move/reseed/repopulate remaining scenery or release rejected occupancy slots. A removal manifest must identify baseline array index/content hash, approved branch band, triangle/solid and measured overlap. Retained records and order must be byte-equivalent to baseline. A point-to-current-branch capsule is not enough: landingRows can widen, crossfall or pass above foliage, and old centreline spacings differ.
4. Use actual changed landing top/underside and upright supports with per-plant extents, including crowns (crownOf), shrub/flower/tuft rendered envelopes. If only a canopy conflicts, do not silently delete a whole stand; report individual removal. Baseline plants genuinely blocking new authorized physical landings are the only proposed exclusions. This has not been measured and no removal is proposed yet.
5. Keep exported plantingClearance tied to actual current geometry for external physical/art checks; introduce a private authored clearance for seeded generation, rather than globally reverting the public query. rockArt.mountainStrata consumes the public clearance and must be compared separately. It has no shared sequential RNG cascade but can add/drop local faces.
6. Also compare district fixtures and pavilion columns: artGeometry reads current SKILL_BRANCHES. District fixture candidate draws precede the keepout decision, so there is no cross-candidate random cascade there; membership can still change. Pavilion columns use a deterministic branch exclusion. Never silently restore a real structure into a changed physical landing. Prop mountainProps uses at/width/path-based spots; it has no direct branch keepout read, but compare exact output rather than infer all downstream dependencies.
