1. **P2 — Seat review cameras after their destination geometry is ready.** `scripts/horizon/capture-mountain-finish.mjs:64–68` queries `geography.surface` before changing the shot and settling the destination. The actual runtime registers `providerWhileDrawn` (`src/harbour/horizon/runtime/index.ts:170`); this provider omits native decks until the region is drawn (`src/harbour/horizon/regions/mountainV2/index.ts:50–52`). Thus a newly visited road/bridge can initially return its terrain or no supporting floor. The selected y is never corrected after loading and the `?? a[1]` fallback still labels it physically seated. Use provisional shot, settle, strict final floor query, seated shot, settle; verify the observed eye is 1.65m over the final supporting floor and fail on missing support.

2. **P2 — Retain console/WebGL failures as capture errors.** All three new capture scripts register `pageerror` only (`capture-mountain-finish.mjs:56`, `capture-mountain-journey.mjs:8`, `capture-native-mountain.mjs:21`). Three's shader-link failure path logs an error without throwing (`node_modules/three/src/renderers/webgl/WebGLProgram.js:877–899`), so page readiness, clock and screenshot count can succeed while materials fail to render. Subscribe to console errors and WebGL context loss and retain them in the result.

3. **P2 — Include native terrain bytes in serial lane identity.** `mountain-final-route-runner.py:27` and `mountain-serial-tests.py:9` hash `public/horizon` but omit `public/mountain`. Native terrain loading reads `public/mountain/terrain/${GEOGRAPHY_REVISION}.bin` (`src/harbour/mountain/terrainAsset.ts:37`). Changing those bytes between jobs is invisible to the lane's sourceStable claim. Add that asset family to both proofs. Native-landings' per-job proof does not bind the other route/test jobs to those same native bytes.

4. **P2 — Bind Horizon/Journey captures to served renderer source.** `capture-mountain-finish.mjs:48` and `capture-mountain-journey.mjs:4` supply assets but no liveSources to `captureEvidence`. Its snapshot proves only local source; matching served baked assets does not establish that a reused Vite server runs this checkout's renderer/harness. Native capture already supplies liveSources. Apply the same raw-source identity checks to the Horizon review entry/runtime and Journey harness/renderer.
