# Decision Log

Living product and architecture decisions for **Hearth**.

Older Sheets-era rows, including superseded ones such as “stay on Sheets until the feature set is stress-tested,” live in [reference/sheets-era/DECISIONS.md](reference/sheets-era/DECISIONS.md). Retired Cursor-era roadmaps (Chapters, Rings, launch essays) live in [nostalgia/](nostalgia/). Those folders are history. Jonathan’s latest instruction, [STRATEGY.md](STRATEGY.md), and the rows below win.

| ID | Status | Decision | Reason |
|---|---|---|---|
| D-001 | Accepted | Git is the canonical source for code, tests, architecture, and release preparation. | Prevent full-file drift. |
| D-002 | Accepted | Keep separate development and production ledgers. | Reversible testing without risking household history. |
| D-005 | Accepted | Jonathan is product owner, production approver, and tie-breaker. | Product tradeoffs belong to the user. |
| D-007 | Accepted | Use calendar months and `America/Toronto`. Week bounds use the civil date, never local midnight. | Match the household and handle DST. |
| D-008 | Accepted | Transfers are neither income nor expense. They are a paired movement between accounts. | Prevent double counting. |
| D-009 | Accepted | Ownership is a splits array that must sum to the amount. Joint is explicit. | Blank member columns will not scale. |
| D-011 | Accepted | Defer bank integrations; keep an import-shaped command path. | Core reliability first. |
| D-015 | Accepted for now | Personal goals and personal ledger rows are a visibility filter, not privacy. Hidden UI is not a security boundary. | Two household editors can share a phone; genuine privacy needs auth. Each person should use their own phone. |
| D-016 | Accepted | Expense leaves purchasing power; income enters; transfer moves between household accounts; refund reduces category spend. Credit-card payments are transfers, not expenses. | Stops the four meanings collapsing into one catch-all. |
| D-018 | Accepted | Exclude live Sheets, ODS exports, `Project Context.txt`, credentials, and other household data from hosted Git history. | Git history is persistent; data exposure adds risk without improving code review. |
| D-020 | Open | Enable two-factor authentication on Jonathan's GitHub account. | The canonical remote still needs it. |
| D-021 | Accepted | CAD is the only currency. Account currency is authoritative. Writers refuse non-CAD active accounts. | No silent USD labels, no amount conversion. |
| D-022 | Accepted | Show an account selector whenever more than one account exists. Seed data includes chequing, Visa, and cash. | Prevent first-active-account from becoming a hidden defect. |
| D-023 | Accepted | Rebuild the working interface as a phone-first web app while keeping the domain portable. | Sheets was the prototype; it is no longer the product. |
| D-025 | Accepted | Browser validation is a usability aid. Commands are the trust boundary. | Stale or altered UI must not write bad money. |
| D-026 | Accepted | One command is one snapshot replace with an undo snapshot. Derived flags refresh after the durable replace. The SQL journal is rebuilt from that snapshot inside a database transaction so the books cannot drift mid-write. | Partial writes cannot exist in this runtime. |
| D-028 | Accepted | One shift is one settings-driven calculation, one source row, one wages income, one tips income. Negative net tips remain allowed. | Preview/post disagreement is a financial bug. |
| D-029 | Accepted | Add Category uses the same commit/undo path as money. | Partial category+budget rows were how CAT-INCOME returned. |
| D-030 | Accepted | Every money row has visibility `household`, `personal`, or `both`, plus `createdBy`. Household view shows household+both. Personal view shows that member's personal+both. | Jonathan and Bianca asked for a shared household database and a personal one each. |
| D-032 | Accepted | Household pairing is a three-word kitchen phrase, a tap-to-join URL, and a Hearth Pass file. A typed six-character blob key is a fallback, not the product. Cloud publish is optional. | Six characters were the wrong object to put in Bianca’s hands. |
| D-033 | Accepted | The books are a double-entry PostgreSQL ledger. Commands still validate and commit an in-memory snapshot; after each commit that snapshot is posted into balanced journal lines. PGlite (Postgres 18) is the in-app engine. The same schema is what you load on hosted Postgres. | JSON blobs cannot enforce debit = credit and cannot produce a trial balance. |
| D-034 | Accepted | Hosted books are the Jonathan/Bianca Supabase Postgres project (`tykhocwacaxwquhynkok`, us-east-1). Schema is live in that project as of 2026-08-21. The app uses the publishable key and PostgREST. The API secret cannot CREATE TABLE. Direct `db.*.supabase.co` is IPv6-only. The publishable key is not a privacy boundary until Auth exists. | Publishable key can read/write tables once they exist; it cannot DDL. |
| D-035 | Accepted | The website is Cloudflare Workers + Assets (`hearth-books`). The books stay on Supabase. SPA join URLs use Wrangler `not_found_handling`, not a catch-all `_redirects` file (Workers API 100324). Builds wipe `dist/` so a cached leftover cannot be uploaded. | Netlify was only serving files and is no longer in the working tree. |
| D-036 | Accepted | Household writes are queued one at a time. Undo tokens carry posted ids so a stale screen still tombstones. Money rows can be removed through the same command/undo path. Reset, the Development/Production pill, reload-demo, and remove ask for confirm. Undo history on this phone is last-in first-out (More → Recent changes). | QA found undo racing the cloud push, an 8-second toast as the only rollback, and one-tap Reset/env switches. |
| D-037 | Accepted | GitHub’s working tree is Hearth. Sheets-era roadmaps, READMEs, decisions, and project context stay under `docs/reference/` and are marked reference-only. Cursor-era Chapter / Ring maps and launch essays stay under `docs/nostalgia/` (D-048). Apps Script source is recovered from git tag `sheets-v0.0.31`, not from the default tree. | Jonathan asked to drop outdated code while keeping history as a map, not a bible. Dual Course later asked the same of the Cursor-era bibles. |
| D-039 | Accepted | Bank, Interac, and issued-card work stay blocked until Auth and RLS exist. Destinations (Open Banking, Interac, tax reserve, issued cards, BaaS) are sequenced by engineering gates on the command kernel, not by pitch-deck month numbers. Jonathan still approves production money movement. Living vision is `docs/STRATEGY.md` (D-048). The Chapter 0–5 essay is nostalgia. | A rival memo named the right company and the wrong order. **Why-note (2026-08-22):** we did not weaken this gate. We stopped pointing at `PRODUCT_ROADMAP.md` as if it were the plan. |
| D-040 | Accepted | Calendar is a first-class tab. The ledger may suggest bills and subscriptions from repeating rows; Google Calendar may overlay both people’s calendars and receive reminder events. Neither path posts money. Adopt uses `addRecurrence`. Mark paid confirms, then `postEntry`. Google tokens stay on this phone (`localStorage` per environment + member). `VITE_GOOGLE_CLIENT_ID` is optional and public. Without it, the month board and an `.ics` file with Toronto alarms still work. | Investors see dates next to the books. The books stay the trust boundary. |
| D-041 | Accepted | The kitchen Worker `hearth-books` goes live from GitHub `main` in one click: merge, or Actions → Cloudflare Workers → Run workflow. GitHub Actions runs `wrangler deploy` (production), not `wrangler versions upload` (preview only). `CLOUDFLARE_API_TOKEN` is cleaned to header-safe characters (quotes, BOM, newlines, HTML entities, leading `Bearer `) before Wrangler; the Cloudflare account id lives in `wrangler.jsonc` (it is not a secret). An empty token fails the job instead of a fake-green skip. Vite bakes `VITE_GOOGLE_CLIENT_ID` at `pnpm build` from a GitHub Actions **variable** (public client ID; never a Google client secret). HTML is `Cache-Control: no-store` and the Worker runs first so a phone cannot keep an old shell. If Cloudflare Workers Builds stays connected, its deploy command must be the same `wrangler deploy` line — `versions upload` leaves the kitchen URL stale. | Merge to main was not publishing. Actions died on quoted/multiline secrets (Wrangler 6111). Workers Builds uploaded preview versions and never promoted them. |
| D-042 | Accepted | Chalkboard notes and the household companion are cosmetics. Commands may scribble, wipe, rename, or equip. They never post money. Mood is computed from Health, bills, goals, and week-over-week spend. Visit streaks stay on the phone. “Punishment” is a face and a sentence, never a fake fee. Conversational Ask is a projection over the books; Power SQL stays read-only. | Daily habit cannot become a second ledger. |
| D-043 | Accepted | Google is the household bridge: identity confirmation and on-demand Google-suite sync (Calendar by default; Drive file-only, Contacts, Gmail read-only, and Sheets read-only as opt-ins). Call `withGoogle` when a feature needs Google or when a linked member confirms a sensitive household action. Tokens stay on this phone. The shared snapshot stores who is linked, never access tokens. Google never posts money. Phrase / join link / Hearth Pass remain how a new phone joins. `VITE_GOOGLE_CLIENT_ID` is optional and public; never store a Google client secret in `VITE_`, Cloudflare, or the repo. | Jonathan and Bianca already live in Google. The books stay the trust boundary. |
| D-044 | Accepted | **The Hercules Update** is the product face: a living Maine Coon who wanders the screen, speaks in compact bubbles, and answers from the journal (`talkHercules` / `askHercules`). **Why-notes (docs rebuild, 2026-08-22)**

- **D-022** still says seed data includes chequing, Visa, and cash. That is the original defect name (hidden first-active-account). Catalog kinds are D-047; `cash` migrates to `other`. We did not rewrite the seed sentence so the bug D-022 prevents stays searchable.
- **Rings and Chapters** are not deleted as *ideas*. They are retired as *indexes of the future*. Shipped rituals (chalkboard, cook-off, sit-down postcard, spectacles, wallet tiles) remain product.
- **Charter “out of scope until the core is boring”** is replaced by unbounded Dual Course vision plus engineering gates. Why: the core is already a general ledger; pretending bank rails are unthinkable was how the old maps went stale, and pretending they are next-week work was how they got dangerous. Auth + RLS still comes first.
