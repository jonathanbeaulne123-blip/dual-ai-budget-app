# Legacy Win memory closure proposal

Inspection against P7 `ba10aa18`: `keepWinAsMemory` in `src/core/chapters.ts` adds the actor to `keptByMemberIds`, then permits `authoredNote` and `hideAmounts` to change without clearing those earlier approvals. The current Win shelf can therefore still present a jointly kept object whose content was never jointly approved in that version. This must not remain a second publication system after exact MemoryComposition approval is enabled.

No Chapter source is edited in this P9 package, as requested by the integration owner. Root P8 integration should close it as follows:

1. Add a dedicated `memory.adopt-win` non-financial authority command accepting `{winId, expectedWinDigest, memoryId}`. Derive the ID deterministically from household + legacy Win ID (a hash avoids collisions with future memory IDs); enforce one adoption mapping and return the original receipt on retry. Read the Win from accepted authority state, not the browser. Keep the historical Win record and its historical `keptByMemberIds` as history.
2. Build a new MemoryComposition with an empty current approval set, no auto-linked photographs, no synthesized authorship and no automatically exposed amounts. Use the recorded meaningful date/title where available. Historical `authoredNote` has no trustworthy author field, so preserve it as an explicitly *unattributed legacy caption*, not as either person's recollection. Add a narrow `legacySource: {kind:'win', winId, digest, unattributedCaption}` metadata field or a separately versioned legacy-caption record; include it in the exact composition digest and shared review. If root declines a new field, show this text as legacy source evidence in the adoption editor and ask for separately authored new recollections; do not silently discard or reattribute it.
3. Adoption itself is not keeping/publication. The two current members separately keep the exact new composition via the existing MemoryPublication flow. Material photo, caption, amount visibility or legacy-caption edits increment the composition and invalidate both approvals.
4. Replace the Win shelf's **Keep as Memory** / caption edit route with **Review as a memory**, opening the deterministic adopted composition in Hearthside Theatre. Existing kept Wins display a migration notice and historical status until reviewed; do not imply that their historic approval applies to the new composition.
5. Once the new capability is active, the authority rejects `keepWinAsMemory` writes from old clients with an upgrade-required error; compatible legacy readers retain old Win history. Do not allow whole-collection legacy writes or financial restore to replace the new MemoryComposition or its receipts. A dismissal of an old unadopted Win must not withdraw a new memory, and memory withdrawal must not delete Win history.

Required tests: duplicate adoption without another memory; missing/changed Win digest; prior keptBy is not imported as approval; unknown historical authorship retained; changed caption/amount visibility invalidates exact approvals; old-client write denial; amount-free adoption; independent withdrawal; financial restore and explicit shared-life recovery without resurrection.
