## Contracts and recovery

`winAdoptionOperation(h, win)` captures `{kind:'memory.adopt-win', winId, memoryId, expectedWinDigest}`. `winMemoryId` hashes version, environment, household ID and Win ID. `winSourceDigest` covers all original Win fields, including legacy visibility, evidence references, timestamps and historical keepers. Private evidence is hashed but not copied into the memory. The timestamp is normalized to ISO only in provenance; its exact original text remains in the source digest and unmodified Win.

`LegacyWinProvenance` v1 contains `kind: 'win'`, `winId`, `sourceDigest`, `recordedAt`, `level`, `unattributedCaption`, and `historicalKeptMemberIds`. Decoder checks reject unknown fields, accessors, sparse arrays and invalid timestamps. Provenance is immutable history. Neither person may silently rewrite it as their own recollection. They may add separately authored present-day recollections through the normal editor.

Adoption always starts with empty current approvals, recollections, media and design references, `hideAmounts: true`, and no linked experience. The existing same-version MemoryPublication path handles keeping. A repeated adoption returns the same existing memory, including newer edits or withdrawal; it cannot reopen, replace, or duplicate it, even if the old Win was dismissed, deleted or financially restored. Source edits before initial adoption require a fresh exact review. Retrying a lost acknowledgement retains the original command identity. Reload recovery finds the same deterministic memory identity.

Dismissal remains independent of memory withdrawal, and historical Win records are not deleted. Existing financial restore/reset/undo preserves the current shared-life graph. Complete authority archive replay retains adoption, its later withdrawal and both receipts. **The separately requested explicit shared-life point-in-time restore workflow remains open; this package does not claim that workflow is implemented.** Parent owns its next implementation package.
