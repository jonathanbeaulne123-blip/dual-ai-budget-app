The weekly, and the metronome

HEARTH_UX_PACKET.md §6.7–6.8 · Clerk slice 4 · Register & Ask slice 10

The weekly is a document that fills in over hours, not a meeting — each sentence in the reading is a focusable control that reveals its own rows. The metronome is a timing-only mark on the Course axis: it carries no amount and no height.

390px · Act 0, the reading

The house spent $2,735.00 this month. Bianca confirmed four motions and held one. September still needs $340.00.

the rows this came from

the metronome — payday ticks on the Course axis

Act 2 (the ask) shows the route drawing only to the member whose ask it is; for the other member it shows the number and any motions raised, with no route and no hours figure. A weekly completes unsigned — never blocked, never nagged. If the charter's cadence is none, no weekly is offered at all. Ticks carry no amount, no height, no value — the contrast between a regular tick and an irregular contribution mark is the information.

A note on provenance

This file did not exist anywhere — not in this repository, not in this project's uploaded documents, not in any chat attachment — until it was built here on 2026-09-04. It is a faithful, literal drawing of every anatomy, geometry, colour, and copy rule HEARTH_UX_PACKET.md already specified in prose (sections 6 and 13); it invents no new design decision of its own. Where the packet gave an exact number (SHELL_VIEW, the type scale, the spacing scale, the token hex values), this file uses that number verbatim, cross-checked against the committed src/styles.css. Where the packet described a screen without giving synthetic content (a note, a category name, a route), this file supplies plausible fictional content in the same voice as the packet's own examples — that content is illustrative, not specified, and a future pixel-level disagreement should defer to the packet's prose and to product judgment, not to this file's invented specifics.

Plates 11 and 14 were cross-checked directly against the already-shipped src/OnboardingChat.tsx and src/onboarding.css (onboarding slice 7) rather than built from the packet alone, since that code was itself built from this same packet section and is the closest thing to ground truth available.
